ХРАНЕНИЕ САЙТА В GITHUB И ПУБЛИКАЦИЯ ЧЕРЕЗ VERCEL
===================================================

Где что хранится:
• GitHub (закрытый репозиторий) — код сайта и история версий.
• Vercel — рабочая интернет-ссылка сайта.
• Supabase — реальные пользователи, школы, поручения, экзамены, документы и настройки.

ПЕРВЫЙ ЗАПУСК
1. Выполните SQL supabase\SETUP_CLEAN_SUPABASE.sql в новом Supabase.
2. Запустите 1_CREATE_PRIVATE_REPO.bat и создайте PRIVATE repository.
3. Скопируйте HTTPS URL созданного репозитория.
4. Запустите 2_UPLOAD_TO_GITHUB.bat и вставьте URL.
5. Запустите 3_DEPLOY_FROM_GITHUB_TO_VERCEL.bat.
6. В Vercel импортируйте репозиторий, Framework = Other, остальные поля пустые.
7. После Deploy скопируйте адрес сайта.
8. Запустите 4_OPEN_SUPABASE_URL_SETTINGS.bat и укажите адрес Vercel как Site URL.
9. В Redirect URLs добавьте адрес Vercel с /** в конце.

ОБНОВЛЕНИЯ
После любых изменений запускайте UPDATE_GITHUB.bat.
Vercel автоматически опубликует новую версию.

После первой загрузки локальную папку можно удалить, но для будущего редактирования
её можно в любой момент снова скачать через GitHub → Code → Download ZIP или Clone.
Рабочие данные при этом не удалятся: они находятся в Supabase.

БЕЗОПАСНОСТЬ
Никогда не добавляйте service_role, sb_secret_, пароль базы или личные пароли.
Publishable key в config.js предназначен для клиентского приложения; безопасность
данных обеспечивают RLS-политики Supabase.
